# Preflight Web — DS build

Static marketing, rule registry and zero-backend Launch Certificate verifier for **Preflight AI**.

Built with **SvelteKit 3 / Svelte 5 runes**, **Tailwind CSS v4**, and `@sveltejs/adapter-static`. Designed for GitHub Pages with no backend, no database and no server-side verification.

## Quick start

```bash
bun install
bun run dev        # http://localhost:5173
bun run build      # static output in ./build
bun run preview    # preview the production build
bun run check      # svelte-check
```

Node 20+ also works with `npm install && npm run build`.

## What is in here

| Route        | Purpose                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------- |
| `/`          | Hero + OS-aware install switcher, interactive terminal simulator, bento, rule explorer, MCP guide, pricing |
| `/rules/`    | Full 43-rule registry with instant search, category filters, vulnerable/fixed code and MCP prompts |
| `/verify/`   | Client-side Ed25519 / WebCrypto Launch Certificate verification with 43-check attestation    |

Shared components live in `src/lib/components/`:

- `HeroTerminal.svelte` — three simulated CLI demos (`scan`, `legal --sync`, `attack`)
- `OsDownloadBar.svelte` — OS detection + latest GitHub release fetch, four install tabs
- `BentoArchitecture.svelte` — six-panel instrument grid
- `RuleExplorer.svelte` — the searchable 43-check registry
- `CertVerifier.svelte` — real Ed25519 signature verification via `crypto.subtle.verify()`
- `McpSetup.svelte`, `Pricing.svelte`, `Navbar.svelte`, `Footer.svelte`, `CodeBlock.svelte`

All rule content lives in `src/lib/data/rules-catalog.json` (37 static rules + 6 active probes).

## Deploy to GitHub Pages

1. Push this directory to a repository.
2. In **Settings → Pages**, set the source to **GitHub Actions**.
3. Push to `main`. `.github/workflows/deploy-pages.yml` builds with Bun and deploys `./build`.
4. Update `static/CNAME` and `src/lib/config.ts` (`domain`, `repo`, marketplace URLs) for your org.

`static/.nojekyll` prevents GitHub Pages from stripping the `_app/` assets.

## Dynamic releases without a backend

`src/lib/releases.ts` fetches:

```
https://api.github.com/repos/<org>/preflight/releases/latest
```

It caches the normalised result in `sessionStorage` for 10 minutes and falls back to the last known tag if the API is rate-limited. Assets are matched by name (`preflight-darwin-arm64`, `preflight-linux-x64`, `preflight-windows-x64.exe`, `preflight-latest.vsix`, `SHA256SUMS.txt`). Publish those names on a release and the download selector updates automatically.

## Certificate verification

`/verify` decodes a Base64URL fragment shaped like:

```json
{ "payload": { "projectName": "...", "overallScore": 100, "...": "..." }, "signature": "<base64url ed25519>" }
```

The payload is canonicalised (sorted keys), then verified with:

```js
crypto.subtle.verify("Ed25519", publicKey, signatureBytes, canonicalPayloadBytes);
```

The demo fixtures are generated by:

```bash
node scripts/generate-demo-certs.mjs
```

That script creates a fresh key pair and writes `src/lib/data/demo-certs.ts` (public key + three signed bundles: verified, blocked, tampered). The private key is **not** committed.

> **Before production:** replace `DEMO_PUBLIC_KEY_B64URL` (and regenerate fixtures) with your real signing key. The demo key is explicitly labelled as a demo in the UI.

Browsers without Ed25519 in WebCrypto show a clear unsupported message rather than a false positive.

## Static installers

- `static/install.sh` — POSIX installer for macOS/Linux; resolves the release asset, verifies SHA-256 when available.
- `static/install.ps1` — Windows PowerShell installer; adds the binary to the user PATH.
- `static/downloads/preflight-latest.vsix` — placeholder fallback; replace with the compiled extension or rely on releases.

Users can install with:

```bash
curl -fsSL https://preflight.dev/install.sh | sh
```
