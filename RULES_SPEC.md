# `RULES_SPEC.md` — Master Detection & Remediation Registry

## Scoring & Blocking Matrix

| Severity       | Score Penalty | Blocks CI / Launch Cert (`blocking`)    | Trigger Threshold                                                                                                                                     |
| -------------- | ------------- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`CRITICAL`** | `-25 pts`     | **`true`**                              | Exploitable data breach, leaked live key, unauthenticated mutation, malware/slopsquatted package, viral copyleft conflict, or runaway financial loop. |
| **`HIGH`**     | `-10 pts`     | `false` (Default) / `true` (`--strict`) | Secondary vulnerability, missing GDPR erasure cascade, unverified clickwrap consent, sub-processor drift, or payment race condition.                  |
| **`MEDIUM`**   | `-4 pts`      | `false`                                 | Defense-in-depth hardening, missing security headers, unencrypted non-critical tokens, accessibility/SEO launch gate.                                 |

**Partial scans** (`scan --changed-only`, agent hooks, IDE incremental `BuildOptions.only`): findings are reported only on changed files, SEC-06 skips git history, and rules tagged `scope: "repo"` (whole-repo absence checks) are skipped: `OPS-01`, `OPS-04`, `SEO-01`, `LEG-03`, `LEG-04`, `LEG-05`, `LEG-06`, `PRIV-02`, `PRIV-06`, `PRIV-07`, `HIPAA-01`, `HIPAA-02`, `LGL-03`, `AIA-01`, `SYS-01`, `SYS-02`, `SYS-03` (Go/Rust handlers are usually registered in an unchanged `main.go`). New rules default to `scope: "file"`; tag a rule `"repo"` when an unchanged file elsewhere could make it fire or clear.

**Profile-only rules** (`profiles` on the rule) run only when one of their profiles is active (`scan --profile airgap`, or `"profiles": ["airgap"]` in config) or when requested by id (`ruleIds`). Today: `SOV-01` (`airgap`) and the compliance packs below (`hipaa`, `fintech-pci`, `legal-privilege`, `eu-ai-act`). Unknown profile names are an error. Any profile, or any profile rule requested by id, needs `requireFeature("profiles")` (agency). Active profiles also **raise** (never lower) existing rules' severities: `hipaa` → PRIV-01/03/05 CRITICAL; `fintech-pci` → PAY-01/02 CRITICAL; `legal-privilege` → VEC-01/VEC-03/PRIV-05 CRITICAL; `eu-ai-act` → LEG-06 CRITICAL (`rules/profiles.ts`). `report.rulesRun` lists what actually ran, so certificates and the checklist never claim a skipped rule passed.

**Optional-grammar rules** (`SYS-01`..`SYS-03`): Go/Rust analysis needs the optional `@ast-grep/napi` ≥ 0.51 plus `@ast-grep/lang-go` / `@ast-grep/lang-rust` (npm install only; the grammars don't embed in the compiled binary). When the repo has Go/Rust sources and they can't load (or `GANTRY_NO_NAPI=1`), Go/Rust routes stay out of `ctx.routes`, the rules throw `RuleSkipped`, and the report carries one `notices[]` entry (`[INFO][…] SKIPPED` in `--compact`) with those ids removed from `rulesRun`. Never a silent clean pass. Body-level route rules (`SEC-07/08/09`, `PAY-01`, `PCI-03`) only analyse TS/JS and Python routes; Go/Rust routes feed `OPS-01`, `PRIV-02`, `PRIV-06` and the pentester.
